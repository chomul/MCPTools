# 시스템 기획서: OUROBOROS: SWARM

## 1. 콘텐츠 개요

OUROBOROS: SWARM은 붕괴한 생체 네트워크를 배경으로 자가 증식 병기 우로보로스를 조작하는 Unity 2D 생존 액션 게임이다. 플레이어는 넓은 필드에서 자동 공격과 자유 이동으로 군집 감염체를 처치하고 몸통을 늘리며, 죽을 때까지 이어지는 무한 생존 기록을 목표로 한다. 10분 보스는 세션 종료 조건이 아니라 첫 대형 마일스톤이다.

몸통은 지속 화력을 높이는 성장 자원이자 위기 시 폭발로 소비하는 전투 자원이다. 몸통을 유지할지 방출해 포위를 벗어날지 선택하는 긴장과, 폭발 후 빠르게 전력을 재건하는 흐름이 핵심 경험이다.

## 2. 핵심 컨셉

### 한 줄 핵심 컨셉

- 몸통을 늘려 지속 화력을 키우고, 포위 순간 몸통을 폭발로 소비해 전장을 뒤집은 뒤 다시 성장하는 2D 군집 생존 액션.

### 플레이어 판타지

- 스스로 증식하며 길어질수록 강해지는 생체 병기를 조종한다.
- 거대한 몸으로 군집을 압도하고, 위기에는 몸의 일부를 과감히 끊어 탈출한다.
- 폭발로 약해진 상태에서도 적을 파고들며 빠르게 전력을 재건한다.

### 설계 기둥

| 기둥 | 실제 플레이 의미 | 목표 감정 |
| --- | --- | --- |
| 성장하는 몸 = 지속 화력 | 몸통을 오래 유지할수록 전투 기여도가 커진다. | 축적의 욕심, 강해지는 만족감 |
| 몸 소비 = 포위 폭발 | 몸통을 포기해 둘러싼 적을 제거하고 이동 공간을 되찾는다. | 결단의 긴장, 전세 역전의 해방감 |
| 폭발 후 재성장 | 약해진 화력으로 생존 동선을 만들며 몸통을 다시 늘린다. | 취약함을 이겨내는 회복감, 다음 폭발에 대한 기대 |

### 핵심 의사결정과 리스크/보상

| 판단 | 보상 | 리스크 |
| --- | --- | --- |
| 몸통을 유지한다 | 높은 지속 화력과 빠른 처치 흐름을 유지한다. | 포위가 완성되면 탈출 여지가 줄어든다. |
| 몸통을 소비한다 | 군집을 제거하고 안전 공간을 즉시 만든다. | 화력이 낮아져 재성장 구간이 위험해진다. |
| 폭발 시점을 늦추거나 앞당긴다 | 더 큰 역전을 노리거나 위험을 일찍 차단한다. | 욕심을 내면 피격 위험이 커지고, 성급하면 소비 효율이 낮아진다. |

### 장르 결합의 플레이 의미

- **생존 액션:** 이동과 자동 공격으로 밀려오는 적 사이에서 생존 동선을 만든다.
- **군집 전투:** 개별 적보다 포위 형태와 밀도 변화를 읽고 폭발 시점을 판단한다.
- **몸통 자원 운용:** 성장 자체가 공격력인 동시에 비상 수단의 재료가 된다.
- **결합 결과:** 미로 없는 넓은 2D 필드에서 길찾기보다 군집의 흐름, 몸통 유지, 폭발 타이밍에 집중한다.

### 경험 목표

- 성장할수록 강해지지만 잃을 것이 커지는 압박을 만든다.
- 포위 직전의 긴장, 폭발 직후의 해방, 재성장의 희망을 반복한다.
- 몸통의 길이와 전장의 빈 공간만으로 현재 강점과 다음 위험을 읽게 한다.

### 피해야 할 방향

- 자동 공격을 지켜보기만 하는 수동적 생존 플레이.
- 몸통 유지 또는 폭발 중 한쪽만 항상 정답이 되는 구조.
- 폭발 후 회복 기회 없이 무력감만 길어지는 흐름.
- 미로 탐색, 복잡한 길찾기, 과도한 장애물 배치가 판단의 중심이 되는 전장.
- 몸통과 적이 많아질수록 위험 신호와 플레이어 상태가 읽히지 않는 화면.

### 프로토타입 검증 질문

- 전제: Unity 2D 기반 PC/Web, 3인 4주 MVP 범위에서 아래 코어 경험만 우선 검증한다.
- 플레이어가 설명 없이도 몸통 성장과 지속 화력 상승의 관계를 이해하는가?
- 포위 상황에서 몸통 유지와 소비 사이에 실제 고민이 발생하는가?
- 포위 폭발이 전장을 뒤집는 만족감과 화력 손실의 부담을 함께 주는가?
- 폭발 후 재성장이 무력 구간이 아니라 다음 반격을 준비하는 플레이로 느껴지는가?
- 미로 없는 넓은 필드에서도 군집 압박, 안전 공간, 몸통 상태를 PC와 Web에서 명확히 읽을 수 있는가?
- 추가 캐릭터 유형이나 복잡한 콘텐츠 없이도 축적·방출·재성장 반복만으로 MVP의 재미를 증명할 수 있는가?

## 3. 핵심 메커니즘

### 3.1 프로토타입 범위와 기준 우선순위

- 플레이 대상은 머리 코어 1개와 이를 따르는 역할형 몸통 세그먼트로 구성된 우로보로스 1종이다.
- `현재 몸통 수`는 머리 코어와 아직 선택하지 않은 생성 요청을 제외한 동시 활성 세그먼트 수다.
- 프로토타입 핵심 범위는 이동, 자동 공격, 몸통 획득과 역할 선택, 역할별 전투 효과, 몸통 피격 절단, 몸통 소비형 포위 폭발, 경험치와 레벨업, 10분 첫 보스 이후 사망까지 이어지는 무한 생존 루프다.
- `콘텐츠기획.md`의 기능 정의와 초기 밸런스 표가 충돌하면 기능 정의를 우선한다. 별도 확정 근거가 없는 아래 수치는 모두 **초기 가설값**이며 ScriptableObject 조정값으로 분리한다.

| 항목 | 프로토타입 규칙 | 채택 기준과 충돌 처리 |
| --- | --- | --- |
| 플레이어 | HP 100, 이동 속도 초당 5.5 | 초기 밸런스 값을 초기 가설로 사용한다. |
| 머리 자동 공격 | 피해 10, 초당 2발, 사거리 6 | 초기 밸런스 값을 초기 가설로 사용한다. |
| 몸통 획득 | 시작 2칸, 몸통 조각 12개당 1칸 생성 요청 | 시작 2칸도 역할을 선택한 뒤 생성한다. 세션 시작 전 2회 연속 선택은 초기 가설이다. |
| 몸통 길이 | 디자인상 제한 없음 | 본문 기능 정의를 우선한다. 초기 밸런스의 최대 20칸은 이전 가설이며 하드 캡으로 사용하지 않는다. 20칸은 초반 세션의 관찰 기준으로만 남긴다. |
| 기술 안전 한도 | 동시 활성 세그먼트 64칸 | Unity/Web 안정성을 위한 **초기 가설값**이다. 게임 규칙·성장 목표·HUD 최대치로 노출하지 않으며 프로파일링 후 조정한다. |
| 지속 화력 | 몸통 1칸당 머리 공격 피해 +4%, 5칸마다 머리 보조 투사체 +1 | 모든 역할 세그먼트가 공통으로 제공하고 역할 효과와 별도 계산한다. |
| 포위 폭발 | 몸통 4칸 이상, 현재 몸통의 30% 소비 | 최신 기능 정의의 30%를 우선한다. 초기 밸런스의 50%는 이전 가설로 취급한다. |
| 폭발 효과 | 실제 소비 1칸당 피해 35, 세그먼트별 반경 1.8 | 초기 밸런스 값을 초기 가설로 사용한다. |
| 피격 | 머리 피격은 HP 감소, 몸통 피격은 HP 감소 없이 절단 | 머리와 몸통의 피해 결과를 분리한다. |
| 보호 시간 | 머리 피격 후 0.6초, 폭발 후 머리 0.4초, 절단 후 몸통 0.35초 | 앞의 두 값은 콘텐츠 기준, 절단 방지 시간은 **초기 가설값**이다. |

- 초기 밸런스의 `최대 몸통 +3` 업그레이드는 무제한 길이 규칙과 충돌하므로 P0 선택지에서 제외한다. 몸통 획득 효율 또는 역할 강화로 교체할지는 검증 후 확정한다.
- 초기 밸런스의 `몸통 역할 중 선택 1개 등장` 표기는 몸통 생성 때마다 플레이어가 4개 역할 전체 중 하나를 고르는 최신 기능 정의와 충돌하므로 이전 가설로 취급한다.

### 3.2 메커니즘 전체 흐름

| 단계 | 시스템 처리 | 플레이 의미 |
| --- | --- | --- |
| 1. 초기 구성 | 전투 시작 전 몸통 역할 4택을 2회 처리하고 선택한 역할 세그먼트를 꼬리에 순서대로 생성한다. | 첫 세션부터 역할 조합을 직접 구성한다. |
| 2. 이동·교전 | 이동 입력으로 머리를 조작하고 머리 자동 공격과 활성 역할 효과를 수행한다. | 군집을 피하면서 역할 조합의 지속 효율을 체감한다. |
| 3. 획득·선택 | 몸통 조각 12개마다 생성 요청 1개를 만들고 전투를 멈춘 뒤 실드·공격·레이저·제어 중 하나를 선택한다. | 길이뿐 아니라 다음 기능을 결정한다. |
| 4. 유지 판단 | 모든 몸통의 공통 화력 보너스와 역할별 효과를 유지하되 몸통 피격·포위 위험을 감수한다. | 긴 몸과 역할 조합을 지킬지 판단한다. |
| 5. 손실·방출 | 몸통 피격 시 피격 지점부터 꼬리까지 절단하고, 포위 폭발 시 꼬리부터 30%를 의도적으로 소비한다. | 비의도적 손실과 의도적 소비를 구분해 대응한다. |
| 6. 재구성 | 남은 역할 조합으로 생존하며 조각을 다시 모아 새 역할 세그먼트를 선택한다. | 약해진 구성을 복구하거나 다른 조합으로 전환한다. |

- 핵심 반복은 `이동·자동 교전 -> 몸통 역할 선택과 축적 -> 유지·절단 대응·폭발 판단 -> 역할 손실 -> 재구성`이다.
- 몸통 길이의 공통 화력, 역할별 효용, 폭발의 순간 군집 제거가 서로 다른 보상 축을 갖도록 한다.

### 3.3 입력 매핑

Unity **New Input System**만 사용한다.

| Action Map / Action | 타입·값 | 기본 입력 | 활성 상태 | 처리 의도 |
| --- | --- | --- | --- | --- |
| `Player/Move` | Value / Vector2 | WASD, 방향키 2D Vector Composite | 전투, 폭발 예고 | 입력 벡터를 정규화해 이동과 마지막 바라보는 방향에 사용한다. |
| `Player/Explosion` | Button / Press | Space | 디버그 전용 | 실제 플레이 발동은 몸통 루프 포위 자동 판정으로 처리한다. Space 입력은 테스트/디버그 전용으로만 사용한다. |
| `UI/Point`, `UI/Click` | Pointer | 마우스 | 몸통 역할 선택, 레벨업 선택 | 카드 포커스와 선택을 처리한다. |
| `UI/Navigate`, `UI/Submit` | Vector2 / Button | 방향키, Enter | 몸통 역할 선택, 레벨업 선택 | 키보드만으로 4택과 3택을 선택한다. |

- 선택 상태에서는 `Player` Action Map을 비활성화하고 `UI` Action Map만 활성화한다.
- 선택 중 눌린 이동 입력은 버리며 전투 복귀 시 예약 실행하지 않는다. 포위 폭발은 선택 상태에서 자동 판정하지 않는다.
- 게임패드와 리바인딩은 별도 확정 전 프로토타입 범위에 포함하지 않는다.

### 3.4 이동과 방향 전환

- `Move`가 0이 아니면 머리 코어가 해당 방향으로 이동하며 대각선도 직선과 같은 속도를 유지한다.
- 바라보는 방향은 마지막 유효 이동 방향을 사용한다. 입력이 0이면 위치와 마지막 방향을 유지한다.
- 머리와 역할 세그먼트의 조준 방향은 이동 방향과 독립적이며 이동 방향을 강제로 바꾸지 않는다.
- 메인 카메라는 머리 코어를 따라가 플레이어가 화면 중앙에 머무르고 맵과 적이 상대적으로 움직이는 느낌을 만든다. 적 스폰 중심도 머리 코어 기준으로 이동한다.
- 머리 코어는 전장 경계와 장애물을 통과하지 않는다. 몸통은 머리가 지나간 경로를 일정 간격으로 순차 추종한다.
- 몸통끼리, 몸통과 머리 사이에는 자기 충돌이 없다. 몸통은 적을 밀거나 적의 이동을 막지 않는다.

### 3.5 머리 자동 공격과 표적 선정

1. 발사 시점마다 머리 기준 사거리 안의 생존 적을 후보로 수집한다.
2. 가장 가까운 적 1개를 표적으로 선정한다.
3. 같은 거리의 후보가 있으면 기존 표적을 유지하고, 기존 표적이 없으면 안정적인 런타임 ID 순으로 선택한다.
4. 유효 표적이 있으면 해당 위치를 향해 발사하고, 없으면 발사와 발사 쿨다운 소비를 생략한다.
5. 표적이 사망하거나 사거리를 벗어나면 다음 발사 시점에 다시 선정한다.

- 정예 우선 조준은 관련 업그레이드를 선택했을 때만 적용한다.
- 폭발 예고 중에는 자동 공격을 유지하고, 몸통 역할 선택·레벨업 선택·사망 중에는 중지한다.

### 3.6 몸통 획득·추종·무제한 길이

| 규칙 | 처리 |
| --- | --- |
| 조각 획득 | 몸통 조각 픽업이 머리에 닿으면 몸통 게이지에 1을 더한다. |
| 생성 요청 | 게이지가 12에 도달할 때마다 12를 차감하고 `대기 중 몸통 생성 요청`을 1개 추가한다. 아직 물리 세그먼트는 만들지 않는다. |
| 역할 확정 후 생성 | 역할 선택이 끝나면 현재 꼬리 끝에 선택 역할 세그먼트 1칸을 생성하고 활성 몸통 수와 공통 화력을 갱신한다. |
| 다중 요청 | 한 번에 여러 요청이 생기면 역할 선택을 요청 수만큼 한 건씩 연속 처리한다. 각 선택 결과는 즉시 꼬리에 추가한다. |
| 추종 | 각 세그먼트는 바로 앞 노드가 지나간 경로를 고정 간격으로 따라 방향 전환을 재현한다. |
| 길이 규칙 | 게임 디자인상 최대 길이는 없다. 20칸을 넘겨도 획득·선택·생성이 계속된다. |
| 기술 안전 한도 | 활성 세그먼트와 대기 중 생성 요청의 합이 64에 도달하면 새 요청을 만들지 않고 게이지를 충족 상태로 보류한다. 공간이 생기면 요청 1개를 즉시 생성한다. 추가 조각은 누적하지 않고 개발 로그에 한도 도달을 기록한다. **초기 가설값**이다. |

- 기술 안전 한도는 크래시와 메모리 폭증을 막기 위한 비상 가드다. 플레이어에게 `최대 64칸`으로 안내하지 않는다.
- 세그먼트 추가·절단·폭발 소비 시 남은 세그먼트의 머리부터 꼬리 순서는 바꾸지 않는다.

### 3.9 몸통 길이에 따른 공통 지속 화력

- 역할과 무관하게 머리 공격 1발의 최종 피해는 `기본 피해 x (1 + 현재 활성 몸통 수 x 0.04)`로 계산한다.
- 머리 보조 투사체 수는 `현재 활성 몸통 수 / 5의 내림값`이며 머리 기본 투사체와 같은 발사 시점·표적을 사용한다.
- 역할 효과는 공통 지속 화력에 추가로 동작한다. 공격·레이저·제어 역할의 피해와 주기는 각 역할 표의 값만 사용한다.
- 역할 세그먼트 생성, 절단, 폭발 소비 직후 다음 머리 발사부터 현재 길이를 반영한다.
- 대기 중 생성 요청과 폭발 예약만 된 세그먼트는 길이 계산을 바꾸지 않는다.

### 3.10 몸통 소비형 포위 폭발

| 항목 | 프로토타입 규칙 |
| --- | --- |
| 발동 조건 | 전투 상태이며 현재 활성 몸통이 4칸 이상이고, 머리와 몸통이 닫힌 루프를 만들었으며, 그 루프 안에 생존 적이 1마리 이상 있고, 폭발 예고·선택·사망 상태가 아닐 때 자동 발동 |
| 소비량 | 포위 발동 시점 활성 몸통 수를 `N`이라 할 때 `K = max(1, ceil(N x 0.30))`칸. 30%는 최신 기능 정의, 올림과 최소 1칸은 **초기 가설**이다. |
| 소비 순서 | 역할 종류와 무관하게 꼬리 끝부터 머리 방향으로 K칸을 예약한다. 실드나 공격 역할을 우선 보존하지 않는다. |
| 예고 | 예약 세그먼트 ID와 위치를 고정하고 0.25초 동안 각 범위와 총 소비 수를 표시한다. 이동·머리 자동 공격·역할 효과는 유지한다. |
| 범위 | 폭발 완료 시까지 남아 있는 예약 세그먼트의 고정 위치마다 반경 1.8의 원을 만들고 합친 영역을 사용한다. |
| 피해 | 실제 소비된 예약 세그먼트 수를 `A`라 할 때 영역 안 각 적에게 `A x 35` 피해를 1회 적용한다. 원이 겹쳐도 같은 적에게 중복 피해를 주지 않는다. |
| 소비·역할 상실 | 피해 판정과 같은 원자 처리에서 남아 있는 예약 세그먼트를 제거하고 각 역할 효과를 즉시 상실한다. |
| 무적 | 유효 폭발 완료 순간부터 머리 코어에 0.4초 무적을 적용한다. 몸통 절단 방지에는 적용하지 않는 것을 **초기 가설**로 둔다. |
| 재사용 | 별도 시간 쿨다운이나 재획득 잠금을 두지 않는다. 같은 포위 상태에서는 1회만 자동 발동하고, 루프가 풀린 뒤 다시 포위 조건이 성립해야 재발동한다. |
| 취소 | 예고 중 사망하거나 남아 있는 예약 세그먼트가 0칸이면 폭발 피해·소비·무적 없이 취소한다. 수동 취소는 없다. |

- 소비 예시는 4칸이면 2칸, 5칸이면 2칸, 10칸이면 3칸이다.
- 폭발 예고 중 몸통이 피격되면 절단을 먼저 적용하고, 제거된 예약 세그먼트를 예고 범위와 소비 목록에서 즉시 제외한다. 예약 세그먼트가 1칸 이상 남으면 시작 시의 4칸 조건을 다시 검사하지 않고 남은 수만 폭발한다.
- 폭발 예고 중 생긴 몸통 생성 요청과 레벨업 요청은 폭발 완료 또는 취소 후 처리하며 현재 폭발의 N·K·A에 포함하지 않는다.
- 발동 조건 미충족 입력은 자원을 소비하지 않고 HUD에 현재 몸통 수와 필요 수만 짧게 표시한다.

### 3.11 머리 코어 피격·HP·사망

- 머리 코어 피격만 HP를 감소시킨다. 유효 피격 시 피해를 차감하고 머리에 0.6초 피격 무적을 적용한다.
- 머리 무적 중 들어온 머리 피격은 HP, 무적 시간, 실드 충전을 변경하지 않는다.
- 같은 적 공격 이벤트가 머리와 몸통 콜라이더를 동시에 겹치면 머리 피격 1건만 후보로 처리해 HP 피해와 절단이 한 이벤트에서 함께 발생하지 않게 한다.
- 서로 다른 공격 이벤트가 같은 틱에 머리와 몸통을 각각 맞히면 머리 피해를 먼저 처리한다. HP가 남으면 몸통 절단도 처리할 수 있다.
- 회복 픽업은 최대 HP를 넘기지 않으며 사망 후에는 적용하지 않는다.
- HP가 0 이하가 되면 즉시 사망 상태로 전이하고 폭발 예고, 대기 중 역할 선택, 레벨업 요청을 취소한다. 이동, 공격, 피격, 픽업, 타이머를 모두 정지하고 결과 데이터를 확정한다.

### 3.12 몸통 피격·절단

- 활성 몸통 세그먼트는 적 접촉과 적 공격의 피격 대상이다. 유효 몸통 피격은 HP를 감소시키지 않는다.
- 머리에서 꼬리 방향의 세그먼트 인덱스를 사용한다. 인덱스 `i`가 맞으면 `i`번 세그먼트부터 현재 꼬리까지 전부 제거한다. 이는 원문의 끊김 범위가 불명확해 채택한 **프로토타입 가설**이다.
- 절단된 세그먼트는 역할 효과와 공통 화력 계산에서 즉시 제외하며 조각·경험치·회복 픽업으로 변환하지 않는다.
- 유효 절단 뒤 전체 몸통에 0.35초 `연속 절단 방지`를 적용한다. 이 시간의 몸통 피격은 절단과 실드 충전 소비 없이 무시한다. 시간은 **초기 가설값**이다.
- 연속 절단 방지는 머리 피격을 막지 않고, 머리 무적은 몸통 절단을 막지 않는다. 폭발 소비는 피격이 아니므로 연속 절단 방지를 발생시키거나 연장하지 않는다.
- 같은 틱에 서로 다른 몸통 세그먼트가 여러 번 맞으면 머리에 가장 가까운 유효 피격 인덱스 1건만 절단하고 나머지는 새 연속 절단 방지로 무시한다.
- 절단 이펙트는 끊긴 경계, 제거되는 꼬리 구간, 상실 역할을 0.5초 안에 식별할 수 있도록 연결선 단절, 세그먼트 소멸 방향, 역할 아이콘 손실을 함께 표시한다.

### 3.13 경험치·픽업·레벨업 흐름

| 순서 | 처리 |
| --- | --- |
| 1. 드롭·수집 | 적 사망 시 경험치, 몸통 조각, 회복 픽업을 생성하고 머리에 닿은 종류별 자원을 반영한다. |
| 2. 요청 생성 | 몸통 게이지 12마다 몸통 생성 요청을, 경험치 요구량마다 레벨업 요청을 각각 만든다. |
| 3. 안전한 진입 | 현재 틱의 피격·절단·폭발 원자 처리를 끝낸 뒤 선택 상태 진입 여부를 판정한다. 폭발 예고 중이면 두 요청을 대기한다. |
| 4. 몸통 역할 선택 | 대기 중 몸통 생성 요청을 먼저 한 건씩 4택으로 처리하고 선택 역할 세그먼트를 꼬리에 생성한다. |
| 5. 레벨업 선택 | 몸통 요청이 없으면 중복 없는 업그레이드 3개 중 1개를 선택하고 즉시 적용한다. |
| 6. 복귀 | 대기 요청이 남으면 우선순위대로 다음 선택을 열고, 모두 끝나면 전투를 재개한다. |

- 선택 상태에서는 모든 전투와 타이머를 일시정지한다. 역할·레벨업 선택 UI를 동시에 겹쳐 표시하지 않는다.
- 경험치, 몸통 조각, 회복은 서로 대체하지 않으며 각 진행도를 독립 보존한다.
- 무제한 길이와 충돌하는 `최대 몸통 +3`은 레벨업 후보에서 제외한다. 그 외 레벨업 3택 규칙은 유지한다.

### 3.14 상태 정의와 전이

| 현재 상태 | 진입 조건 | 상태 중 처리 | 종료 조건·다음 상태 |
| --- | --- | --- | --- |
| 시작 몸통 선택 | 세션 시작, 시작 생성 요청 2개 | 전체 전투 정지, 역할 4택만 처리 | 요청 2개 완료 -> 전투 |
| 전투 | 시작 선택 완료 또는 모든 선택 종료 | 이동, 자동 공격, 역할 효과, 피격, 픽업, 폭발 입력 처리 | 유효 폭발 -> 폭발 예고, 요청 있음 -> 몸통 역할 선택 또는 레벨업 선택, HP 0 -> 사망 |
| 폭발 예고 | 전투에서 폭발 조건 충족 | 이동·공격·피격·절단 유지, 예약 범위 표시, 선택 요청 대기 | 0.25초 완료 -> 절단 반영 후 폭발 처리 -> 몸통 역할 선택, 레벨업 선택 또는 전투; HP 0 -> 사망 |
| 몸통 역할 선택 | 생성 요청이 있고 폭발 원자 처리 종료 | 전체 전투 정지, 역할 4택만 처리 | 요청 완료 -> 다음 몸통 역할 선택, 레벨업 선택 또는 전투 |
| 레벨업 선택 | 몸통 요청이 없고 레벨업 요청이 있음 | 전체 전투 정지, 업그레이드 3택만 처리 | 요청 완료 -> 다음 레벨업 선택 또는 전투 |
| 사망 | HP 0 이하 | 모든 전투·선택 입력과 판정 정지, 결과 확정 | 현재 세션 내 복귀 없음 |
| 머리 무적 플래그 | 유효 머리 피격 또는 폭발 완료 | 기본 상태와 병행, 머리 피해만 무시 | 남은 시간 종료 시 해제 |
| 연속 절단 방지 플래그 | 유효 몸통 절단 | 전투·폭발 예고와 병행, 몸통 절단만 무시 | 0.35초 뒤 해제 |

- 선택 요청 우선순위는 `몸통 역할 선택 -> 레벨업 선택`이다. 두 선택 모두 중첩 창이 아니라 직렬 상태로 처리한다.
- 폭발 예고는 전투의 원자 행동이므로 예고 중 생성된 선택 요청보다 먼저 완료하거나 취소한다.

### 3.15 동시 이벤트 우선순위·입출력·예외

같은 FixedUpdate에서 이벤트가 겹치면 다음 순서로 확정한다.

1. 동일 공격 이벤트의 중복 콜라이더 접촉을 제거하고 머리 무적·연속 절단 방지 등 무효 조건을 판정한다.
2. 유효 피격을 막을 수 있는 실드 1개의 충전을 소비한다.
3. 막히지 않은 머리 피해를 적용하고 HP 0이면 즉시 사망한다. 사망하면 이후 절단·폭발·선택을 처리하지 않는다.
4. 생존 중인 경우 몸통 절단 후보 중 머리에 가장 가까운 1건을 적용한다.
5. 같은 틱에 폭발 예고 시간이 끝났다면 절단 후 남은 예약 세그먼트만 피해·소비한다.
6. 픽업과 경험치 결과로 몸통 생성·레벨업 요청을 만든다.
7. 대기 요청이 있으면 몸통 역할 선택을 먼저, 레벨업 선택을 나중에 연다.

| 입력·조건 | 정상 출력 | 충돌·예외 처리 |
| --- | --- | --- |
| `Move` 유효 벡터 | 정규화 이동, 방향 갱신, 몸통 추종 | 선택·사망이면 무시, 0 벡터면 정지·마지막 방향 유지 |
| `Explosion` Press | K칸 예약, 0.25초 예고 후 실제 A칸 피해·소비 | 4칸 미만·선택·사망이면 무소비, 예고 중 재입력 무시 |
| 몸통 조각 12개 | 생성 요청 1개 | 폭발 예고 중에는 선택만 지연, 기술 안전 한도면 게이지 충족 상태로 보류 |
| 역할 선택 확정 | 선택 역할 1칸을 현재 꼬리에 생성 | 선택 중 절단·폭발은 정지되어 발생하지 않으며 전투 입력은 버림 |
| 경험치 요구량 충족 | 레벨업 요청 1개 | 역할 요청과 동시이면 역할 선택 완료 뒤 3택 표시 |
| 머리 피격 | 실드가 없으면 HP 감소와 머리 무적 | 같은 공격이 몸통도 겹치면 절단하지 않음, HP 0이면 모든 대기 요청 취소 |
| 몸통 피격 | 실드가 없으면 피격 세그먼트부터 꼬리까지 절단, HP 불변 | 연속 절단 방지 중 무시, 폭발 완료와 동시이면 절단 우선 |
| 폭발 예고 중 절단 | 예약 목록에서 잘린 세그먼트 제외, 표시 갱신 | A가 0이면 무효 취소, A가 1 이상이면 남은 수로 피해·소비 |
| 폭발 소비 | 꼬리부터 역할 무관 30% 올림 소비, 역할 즉시 상실 | 대기 중 생성 요청은 소비 대상이 아니며 같은 세그먼트를 절단과 폭발로 이중 제거하지 않음 |
| 활성·대기 합 64 | 새 생성 요청 보류와 개발 로그 | 게임상 최대치로 표시하지 않고 절단·소비로 공간이 생기면 요청 재개 |

### 3.17 남은 검증 질문

- 몸통 피격의 `끊김`은 피격 세그먼트만 제거하는가, 피격 세그먼트부터 꼬리까지 제거하는가? 프로토타입은 후자를 채택한다.
- 연속 절단 방지는 전체 몸통 공용 0.35초가 적절한가, 세그먼트별 보호나 더 긴 시간이 필요한가?
- 실드는 적대 피격 1건을 막는가, 원문 표현처럼 적 개체의 보호막 진입 자체를 1회 차단해야 하는가?
- 폭발 후 0.4초 무적은 머리 HP만 보호하는가, 몸통 절단도 함께 막아야 하는가? 프로토타입은 머리만 보호한다.
- 30% 폭발을 최소 몸통 4칸 조건만으로 연속 사용할 수 있어도 축적·방출·재성장 리듬이 유지되는가?
- 시작 몸통 2칸을 위한 연속 4택이 첫 플레이 진입을 지연하는가? 필요하면 시작 프리셋 후 첫 획득부터 선택하는 안과 비교한다.
- 동시 활성 세그먼트 기술 안전 한도 64가 PC/Web 성능과 무제한 성장 체감 사이에서 적절한가?

### 검증원칙

- 요청은 시스템 경계에서 한 번 검증한다. 입력 콜백, 충돌 콜백, 공개 명령, SO 로드 경계에서 상태·참조·유한 수·범위·안정 ID를 확인하고 내부 흐름은 검증된 값만 사용한다.
- 무효 요청은 무부작용이어야 한다. HP, 몸통, 게이지, 쿨다운, 예약, 풀 사용량, 선택 대기열을 변경하거나 후속 이벤트를 만들지 않는다.
- 공격·픽업·선택·폭발 이벤트는 안정 이벤트 ID와 전투 틱으로 중복을 제거한다. 한 원인에서 상태 이벤트와 피드백 이벤트는 각각 최대 1회만 발행한다.
- 동일 FixedUpdate는 4.18의 우선순위를 따른다. 콜라이더 콜백 도착 순서, GameObject 계층 순서, 플랫폼별 물리 순서에 결과를 맡기지 않는다.
- ScriptableObject는 읽기 전용 원본이다. 시작 시 OSSessionRuntimeState와 역할별 런타임 상태로 값을 복사하고 플레이 중 원본 필드나 목록을 변경하지 않는다.
- 필수 참조 null, 중복 ID, 잘못된 Action 타입, 음수 시간·피해·거리, 0 이하 요구량, 배열 범위, NaN·Infinity를 시작과 요청 경계에서 검증한다.
- Web 성능 한도는 활성 적 180, 투사체 120, 활성·대기 몸통 합 64를 1차 가설로 검증한다. 한도 도달 시 추가 생성을 안전하게 거부·보류하고 기존 전투를 유지한다.

### 응답원칙

- 규칙 명령은 bool만 반환하지 않고 OSResultCode 또는 OSRuleResult<T>를 사용한다. 성공, 대기, 상태 거부, 범위 거부, 중복, 용량 거부, 사망 취소, 예약 소멸, 설정 오류를 구분한다.
- ReasonKey는 HUD가 플레이어용 실패 이유를 구분하고 로그가 개발 설정 오류를 구분할 수 있는 안정 키다. 표시 문구 자체를 규칙 코드에 넣지 않는다.
- 상태를 완전히 확정한 뒤 관련 이벤트를 1회 발행한다. 이벤트 구독자가 원본 명령을 다시 실행하지 않으며, 피드백 실패가 규칙 확정을 되돌리지 않는다.
- 몸통 부족, 대상 없음, 무적, 절단 방지, 선택 중 입력, 풀·기술 한도 같은 게임 규칙 실패는 예외가 아니라 정상 거부 결과다.
- 필수 SO·프리팹·InputActionReference 누락, 중복 데이터 ID, 불가능한 범위 같은 개발 설정 오류만 명확한 오류 로그를 남기고 해당 기능을 비활성화한다. 반복 프레임 로그는 금지한다.

### 주석 규칙과 최소 시그니처 예시

- 모든 프로젝트 고유 클래스에 XML summary로 완결 책임과 소유하지 않는 책임을 적는다.
- 모든 public 함수와 상태 변경·우선순위 처리·예약 소비 같은 핵심 private 함수에 XML summary를 둔다. 역할, 성공 시 부작용, 실패 조건을 적고 매개변수와 결과가 자명하지 않으면 param과 returns를 추가한다.
- Unity 콜백은 어떤 이벤트를 수집하거나 어느 상태에서 실행되는지 주석으로 밝힌다. 자명한 대입·분기·반복을 줄별로 설명하는 주석과 구현을 그대로 번역한 주석은 금지한다.
- 아래는 형식 확인용 유일한 C# 예시이며 전체 구현 예시가 아니다.

    /// <summary>
    /// 역할 선택 결과를 현재 꼬리에 추가한다. 성공 시 체인 순서를 변경하고
    /// ChainChanged를 한 번 발행하며, 한도 또는 참조 오류에서는 상태를 바꾸지 않는다.
    /// </summary>
    /// <param name="role">새 세그먼트에 부여할 네 역할 중 하나.</param>
    /// <returns>생성된 안정 ID 또는 구분 가능한 거부 이유.</returns>
    public OSRuleResult<int> AppendSegment(OSBodyRoleType role);

### 4.18 상태 전이, 동시 이벤트 우선순위 및 예외

같은 FixedUpdate의 확정 순서는 아래와 같으며 OSGameSessionController만 이 순서를 실행한다.

| 우선순위 | 처리 |
| ---: | --- |
| 1 | 안정 공격 ID로 동일 공격의 다중 콜라이더를 제거한다. 같은 공격이 머리와 몸통에 닿으면 머리 후보 1건만 남기고 무적·절단 방지 등 명백한 무효 조건을 판정한다. |
| 2 | 유효 적대 피격에 사용할 수 있는 실드 1개의 충전을 소비한다. |
| 3 | 막히지 않은 머리 피해를 적용한다. HP가 0 이하면 즉시 사망하고 이후 절단·폭발·픽업·선택을 처리하지 않는다. |
| 4 | 생존 중이면 몸통 절단 후보 중 머리에 가장 가까운 인덱스 1건을 적용한다. |
| 5 | 같은 틱에 폭발 예고가 끝났으면 절단 후 남은 예약 세그먼트만 피해·소비한다. |
| 6 | 중복 제거된 픽업을 종류별 진행도에 적용하고 몸통 생성·레벨업 요청을 만든다. |
| 7 | 폭발이 끝났고 대기 요청이 있으면 Body 요청을 모두 먼저, LevelUp 요청을 나중에 직렬 개방한다. |

| 항목 | 명세 | 항목 | 명세 |
| --- | --- | --- | --- |
| 필요한 클래스 | OSGameSessionController, OSCombatEventBuffer, OSSelectionQueue, OSExplosionController, OSPlayerHealth, OSBodyChain | 입력 | 물리 콜백에서 수집한 틱·이벤트 ID 기반 피격·픽업 후보, 폭발 완료 신호, 현재 상태 |

### 4.24 QA 자동화 및 Windows/WebGL 빌드·목업 폴백 게이트

4.22의 테스트 행렬과 성능 수치를 개별 검증 기준으로 유지하고, 아래는 주차별 실행 순서와 빌드 차단 여부만 추가 정의한다.
