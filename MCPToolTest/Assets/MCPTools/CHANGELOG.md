## [0.3.0] - 2026-07-26

> 이 릴리스는 Task 6-1(스프라이트 시트 애니메이션) · Task 9(테스트·CI·배포 온보딩) ·
> Task 10(정확성·견고성) · Task 8(메모리·성능·속도)의 결과를 함께 담습니다.
> **동작이 바뀌는 변경**이 포함되어 MINOR를 올립니다 — `mcptools_run_pipeline`이 완료까지
> 블로킹하지 않고 즉시 `started`를 반환하며, `unloadModelsAfterBatch` 기본값이 `false`가 됩니다.

### Added

- 스프라이트 시트: **동작별 AnimationClip 자동 생성** — `Tools/MCP/Sprite Sheet` 창의 "4. 애니메이션" 섹션과 MCP 도구 `mcptools_spritesheet_build_clips`. 서브 스프라이트를 `{동작}_{번호}`로 묶어 `Assets/Generated/3_Confirmed/Animations/{시트이름}/{동작}.anim` 생성(프레임 레이트·루프 지정, idle/walk/run 기본 루프 ON). 기존 클립은 새로 만들지 않고 커브·프레임 레이트·루프만 갱신해 Animator 참조와 애니메이션 이벤트를 보존
- 스프라이트 시트: **AnimatorController 생성 옵션** — 동작별 State 배치, 기존 컨트롤러에는 없는 State만 추가(트랜지션·파라미터 보존), 대상 프리팹 지정 시 루트에 Animator 부착 + 컨트롤러 연결(Undo 지원)
- 스프라이트 시트: 임포트 **전용 행 목록**(1번 프롬프트 섹션과 분리, 행 추가/삭제/순서 변경/[1번 행 목록 가져오기])과 **검출 → 확인 → 적용 2단계 흐름** — 검출 결과 표에서 행별 동작명을 직접 입력하고 프레임별 썸네일·포함 체크로 제외할 수 있음
- `mcptools_spritesheet_import`에 `dryRun` 파라미터 — 배경 제거·격자 검출 결과(행 수, 행별 프레임 수, 셀 크기, 자동 제외된 빈 셀)만 반환하고 아무것도 기록하지 않음
- 4단계: **스프라이트 시트의 특정 프레임 적용** — 항목의 `spriteName`(예: `walk_03`)과 `spriteSheetPath`. `mcptools_apply_asset`에도 `spriteName` 파라미터 추가
- 4단계: **AnimatorController 자동 연결** — 시트를 고르면 그 시트에서 만든 컨트롤러(`Animations/{시트이름}/{시트이름}.controller`)를 찾아 [적용] 시 대상 프리팹 루트에 Animator를 붙여(있으면 재사용) 함께 연결합니다. 한 시트의 클립·컨트롤러는 한 벌뿐이므로 따로 고르지 않고, 연결될 대상만 창에 표시합니다. 스프라이트 적용과 같은 저장에서 처리되고 Undo 가능하며, 컨트롤러의 클립 커브 경로가 그 프리팹에 없으면 적용 전에 검증에서 걸러 안내합니다(씬 항목 미지원). 다른 컨트롤러를 쓰려면 항목의 `animatorControllerPath`(JSON 또는 MCP 파라미터)로 덮어쓸 수 있고, `mcptools_apply_asset`/`_apply_all`은 `linkedControllerPath`를 반환합니다
- 4단계: 스프라이트 시트를 **썸네일 그리드에서 그림을 보고 선택** — 항목 상세의 [시트 고르기 (썸네일)]에서 `Generated/3_Confirmed/SpriteSheets/`의 시트를 클릭해 고릅니다(선택 항목 강조, [해제]로 미지정)
- 설정 `spriteAnimationFrameRate`(기본 12), 출력 폴더 `Generated/3_Confirmed/Animations`
- README에 스프라이트 시트 도구 사용법 절 추가(기존 누락분)
- **Play Mode·컴파일 중 MCP 도구 가드** — 에디터가 재생 중이거나 스크립트 컴파일/에셋 임포트 중이면 도구를 실행하지 않고 원인·조치를 담아 실패합니다(그 상태의 `AssetDatabase.Refresh()`가 도메인 리로드를 일으켜 진행 중인 생성과 플레이 세션을 함께 끊기 때문). 읽기 전용 진단 도구 `mcptools_ping`·`mcptools_status`·`mcptools_list_candidates`는 예외로 허용합니다(`list_candidates`는 생성 Job 폴링 경로). 각 창의 생성·확정·적용·스캔·저장 버튼도 같은 조건에서 비활성화되고 사유를 표시합니다
- **4단계 적용 이력** — 적용에 성공하면 `Generated/3_Confirmed/GenerationResults.json`의 새 `applications` 배열에 항목 id·대상·적용한 에셋 경로·적용 시각을 기록합니다. 창을 닫았다 다시 열어도 "적용됨" 배지가 유지되고, **[일괄 적용]이 이미 적용한 항목을 건너뛰어** 불필요한 프리팹 재저장과 git diff를 만들지 않습니다("이미 적용됨 N개" 표시). 개별 [선택 적용]은 이미 적용한 항목에도 항상 가능합니다. 1단계 산출물(AssetList JSON)은 건드리지 않습니다
- **적용 전 프리팹 모드 검사** — 대상 프리팹이 프리팹 모드로 열려 있고 저장하지 않은 변경이 있으면 적용을 막고 안내합니다(그대로 적용하면 미저장 변경까지 함께 디스크에 저장되어 되돌릴 수 없음). 프리팹 모드의 Auto Save는 Unity 기본이 켜짐이라 평소에는 해당하지 않습니다
- **문서 스키마 버전** — AssetList / PromptSet / GenerationResults 최상위에 `schemaVersion`(정수, 현재 1) 추가. 키가 없는 구버전 파일은 1로 간주해 그대로 읽고, 아는 버전보다 크면 경고만 남기고 계속 진행합니다(막지 않음)
- **항목 id 충돌 경고** — 서로 다른 id가 파일명 변환 후 같아지면(예: `hero:idle`·`hero/idle` → `hero_idle`) 3단계 후보·확정본이 서로 덮어써집니다. 1단계 저장 시 검출해 `mcptools_asset_list_save`의 `warnings`와 1단계 창 안내로 알리고(저장은 막지 않음), 3단계에서 다른 항목의 후보 폴더를 지우거나 확정본을 덮어쓰게 되면 콘솔 경고를 남깁니다
- **브리지 서버 Host 헤더 검증** — 루프백 바인딩 시 `Host`가 `127.0.0.1`/`localhost`/`::1`(포트 일치 또는 생략)이 아니면 403. 사용자가 방문한 웹페이지가 단순 요청으로 `/generate`·`/free`·`/shutdown`을 호출하는 것을 막습니다. `--host`로 외부 바인딩한 경우는 접속 호스트명을 서버가 알 수 없어 검증을 끄고 기동 시 경고를 출력합니다
- **브리지 서버 입력 상한** — `count`는 1~32(초과·정수 아님은 조용히 잘라내지 않고 400으로 거절), 요청 본문은 1 MiB(`/upload`만 64 MiB), `Content-Length` 누락·비숫자도 400
- **통합 창에 스프라이트 시트 진입점** — 파이프라인 4단계 아래에 "스프라이트 시트 (선택)" 안내 블록과 [Sprite Sheet 창 열기] 버튼. 산출물이 항목별 확정본과 다른 위치에 저장되어 단계 상태 배지에 잡히지 않는다는 점도 함께 안내합니다
- **시트 저장 덮어쓰기 안내** — 같은 이름의 시트를 덮어쓸 때, 창은 확인 다이얼로그로 묻고(취소하면 저장·슬라이스하지 않음) MCP는 응답의 `overwroteExisting`으로 덮어썼음을 알립니다. 이전에는 무경고로 덮어썼습니다
- **브리지 `GET /workflows?refresh=1`** — `/object_info` 캐시와 워크플로 JSON 캐시를 즉시 무효화합니다

### Changed

#### 성능 (Task 8)

- **연속 생성에서 모델 재로드 대기 제거** — `unloadModelsAfterBatch` 기본값을 `true` → **`false`** 로 바꾸고, **단건 생성 경로의 언로드 호출을 제거**(일괄 경로만 유지)했습니다. 이전에는 "후보 4개 생성"을 연속으로 누를 때마다 체크포인트가 언로드·재로드되어 SDXL/Flux 계열 기준 **회차당 약 10~40초가 순수 대기로** 붙었습니다. 이미 설정 에셋을 가진 기존 사용자를 위해 **1회성 마이그레이션**(`settingsVersion`)을 함께 넣었습니다 — 값이 실제로 바뀐 경우에만 콘솔에 안내와 되돌리는 방법을 출력하고, 그 뒤로는 다시 보정하지 않습니다. VRAM이 부족하면 설정에서 다시 켤 수 있습니다(README에 트레이드오프 기록).
  **절감 폭은 모델 크기에 크게 좌우됩니다** — RTX 4070 12GB + SD 계열 워크플로에서 실측한 결과 언로드 직후 생성과 연속 생성의 차이가 회차 간 편차(±10초) 안에 묻혀 유의미한 절감이 관측되지 않았습니다. 위 10~40초는 SDXL/Flux 6~12GB 기준 추정치입니다
- **`mcptools_run_pipeline`이 에디터를 멈추지 않습니다 (동작 변경)** — 완료까지 메인 스레드를 블로킹하던 것을 **Job 모델로 전환**해 즉시 `{status:"started", …}`를 반환합니다. 10항목이면 5~10분 동안 에디터가 통째로 얼어붙던 문제가 사라집니다. 진행 상황과 최종 결과(`pendingSelections`/`applied`/`failed`)는 **`mcptools_status`의 새 `pipeline` 블록**으로 폴링하며, 필드 이름과 형태는 그대로입니다. Job은 동시에 1개만 실행되고 `항목 수 × jobTimeoutSeconds` 타임아웃이 걸립니다
- **파이프라인의 항목별 `AssetDatabase.Refresh()` 제거** — `GenerateAsync`에 `refreshAssets` 인자를 추가해 파이프라인은 생략하고 루프 종료 후 1회만 Refresh합니다. 10항목이면 프로젝트 전체 스캔이 10회 → 1회
- **4단계 창의 리페인트 비용 제거** — 상세 패널이 매 리페인트마다 프리팹을 로드하고 계층을 순회해 경로 목록을 만들고 `SerializedObject`까지 생성하던 것을, 선택 변경·대상 편집 시점에만 계산해 캐시합니다. 항목 카운트도 상태 변경 시점에만 갱신합니다
- **일괄 적용 배치화** — 같은 프리팹을 대상으로 하는 항목들을 그룹으로 묶어 **프리팹 1회 로드 → 전체 할당 → 저장 1회**로 처리합니다(이전에는 항목 수만큼 반복 저장). 배치 전체를 `StartAssetEditing`/`StopAssetEditing`으로 감싸고, 확정본 경로 기록은 배치 시작 시 1회만 읽습니다(이전에는 항목마다 JSON 전체 재파싱)
- **1단계 스캔 최적화** — 프리팹·씬 루트당 계층을 4번 순회하던 것을 **1회**로 통합하고, 컴포넌트 타입 판정 결과를 타입별로 캐시합니다. 슬롯 순서는 기존과 동일하게 보존됩니다(순서가 바뀌면 항목 id가 달라지므로)
- **시트 임포트 알고리즘** — pocket 침식을 분리 가능 필터로 바꿔 O(N·K²) → **O(N)**, 격자 경계 검출의 전체 픽셀 스캔을 2회 → **1회**로 통합했습니다. 검출 결과는 기존과 완전히 동일합니다
- **브리지 폴링 지연 축소** — 완료 확인 전에 먼저 1초를 자던 것을 루프 끝으로 옮기고 간격을 1.0초 → 0.3초로 낮췄습니다. Unity 쪽 폴링도 0.3초 시작 + 지수 백오프(상한 1.5초, 진행률이 오르면 초기값으로 리셋)로 바꿨습니다
- **브리지 캐시** — `/object_info`를 60초 TTL로 캐시하고(캐시를 내주기 전 ComfyUI 생존만 별도 확인), 워크플로 JSON을 mtime 기반으로 캐시합니다. `/workflows` 응답 1건에 워크플로 JSON을 (워크플로 수 × 2)회 읽던 것이 1회로 줄었습니다
- **`SerializedObject` 누수 해소** — 생성 후 해제하지 않던 4곳(4단계 적용 2곳, 오디오 필드 검증, 1단계 스캔)을 `using`으로 감쌌습니다. 특히 4단계 창은 매 리페인트마다 생성하고 있었습니다
- **`MCPToolSettings.GetOrCreate()` 정적 캐시** — 호출마다 `AssetDatabase.FindAssets`를 실행하던 것을 도메인 리로드당 1회로 줄였습니다
- **리페인트마다 `EditorPrefs.SetString` 호출 제거** — 값이 바뀐 경우에만 저장합니다 (Windows에서는 레지스트리 쓰기였습니다)
- 브리지 서버 버전 0.2.0 → **0.4.0** — 0.3.0에서 Host 검증·입력 상한, 0.4.0에서 폴링 간격 축소·`/object_info` 60초 캐시·`?refresh=1`

#### 그 외

- **MCP 경로에서 모달 다이얼로그를 띄우지 않습니다.** `CandidateGenerator.GenerateAsync`에 `interactive` 인자를 추가해(기본 `false`) 창은 기존처럼 다이얼로그로 안내하고, MCP·파이프라인 경로는 같은 원인·조치를 담은 예외만 던집니다. 이전에는 `mcptools_generate_candidates` 호출 시 사전 검증에 실패하면 에디터가 모달로 잠긴 채 Job이 `running`으로 남았고, `mcptools_run_pipeline`은 스레드풀에서 `DisplayDialog`를 불러 메인 스레드 위반 예외가 preflight 안내를 덮어썼습니다. 비대화형 실패는 `OperationCanceledException`이 아닌 `InvalidOperationException`으로 던져 "사용자 취소"로 오인되지 않게 했습니다
- AssetList의 `status` 필드를 **1단계에서 사람이 관리하는 자유 입력 열**로 문서화했습니다. 파이프라인이 자동으로 전진시키지 않으며, 적용 여부는 위 `applications` 기록으로 관리합니다

- 스프라이트 시트 임포트가 **자동 행 이름(`rowN`)을 붙이지 않습니다.** 이름이 빈 행이 있으면 창에서는 [슬라이스 적용]이 비활성화되고, MCP 경로는 어느 행의 이름이 비었는지 알리며 실패합니다. 시트 위/아래의 얇은 여백 줄이 행으로 검출돼 엉뚱한 동작명이 붙고 빈 스프라이트가 만들어지던 문제를 사용자가 직접 확인·수정하는 방식으로 해결
- 프레임 번호는 **포함한 프레임만** 1부터 연속으로 부여
- 격자 검출에서 **"비어 보임"으로 나온 셀을 자동 제외**합니다(전경 픽셀 비율 2% 미만). 체크를 일일이 해제하지 않아도 프레임이 없는 것처럼 처리되고, 전부 자동 제외된 행은 통째로 빠져 동작명도 필요 없습니다. 실제 콘텐츠였다면 창에서 해당 셀을 다시 체크해 되살릴 수 있으며, 자동 제외 개수는 검출 완료 메시지와 MCP 응답(`autoExcludedEmptyFrameCount`)에 표시됩니다
- 행 동작명은 **자동 제외 후 남은 행에만** 위에서부터 순서대로 배정됩니다(여백 밴드 행 때문에 이름이 밀리던 문제 해소)
- 4단계 창의 **스프라이트 시트 지정이 썸네일 선택기**로 바뀌었습니다 — 프로젝트 전체 ObjectField 대신 `Generated/3_Confirmed/SpriteSheets/`의 시트를 그림으로 보고 고릅니다(창에 포커스가 올 때마다 목록 갱신)
- 4단계 창에서 **스프라이트 이름 입력·이름 선택 드롭다운을 제거**했습니다. 시트를 고르면 **첫 프레임**이 적용됩니다(Sprite Mode=Multiple 시트는 에셋 전체 스프라이트가 없어 이전에는 null이 적용될 수 있었습니다). `spriteName` 데이터와 MCP 파라미터는 그대로라 특정 프레임 지정도 계속 가능합니다

### Fixed

- 4단계에서 RawImage 대상에 `spriteName`을 지정하면 조용히 무시된 채 시트 전체가 적용되던 문제 — 검증에서 걸러 원인·조치를 안내

> 격자 검출·배경 제거·셀 콘텐츠 판정·피벗 계산 알고리즘은 변경하지 않았습니다(분리 품질 유지). "비어 보임" 자동 제외는 검출된 셀의 기본 포함 여부만 바꾸며, 셀 후보를 만드는 판정 기준(0.5%)에는 관여하지 않습니다.

- 3단계: 후보 개수를 생성 창에서 바로 조절하는 슬라이더(1~12, 설정 에셋 `candidateCount`와 공유)
- 3단계: 이 세션이 시작하지 않은 브리지 서버를 내리는 **[원격 종료]** 버튼, 브리지 서버 `POST /shutdown` 엔드포인트
- Unity 에디터 종료 시 이 도구로 시작한 브리지 서버를 자동 종료 (설정 `shutdownBridgeOnEditorQuit`, 기본 켬)
- 단계별 산출물 하위 폴더 — `Docs/1_AssetList`·`Docs/2_PromptSet`·`Docs/SpriteSheetPrompt`, `Generated/3_Candidates`·`Generated/3_Confirmed`(`Images`/`Audio`/`SpriteSheets`). 기존 프로젝트의 구 위치 파일도 계속 인식됩니다(읽기는 양쪽, 쓰기는 새 위치)

### Changed

- 브리지 서버 버전 0.1.0 → 0.2.0 (`/shutdown` 추가)
- 3단계 일괄 생성이 항목별 기본 워크플로 대신 **현재 선택된 워크플로와 변수 값**을 모든 대상에 적용(프롬프트만 항목별 값). 참조 이미지 업로드는 일괄 1회로 통합
