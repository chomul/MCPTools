# Task 6 — SpriteSheet 도구 (외부 AI 기반)

> 배경: 로컬 ComfyUI 영상 생성이 어려워, 스프라이트 시트는 외부 AI(Codex/GPT 이미지 등)에 프롬프트를 붙여넣어 생성하는 AI 중립 경로로 진행한다.

## 1. 목표

레퍼런스 이미지 첨부를 전제로 여러 동작을 행(Row)별로 담은 통합 스프라이트 시트 프롬프트를 생성하고(복사/붙여넣기), 외부 AI가 생성한 멀티 행 시트 이미지를 배경 제거·정규화해 Unity Sprite Multiple 슬라이스까지 자동화한다.

## 2. 구현 항목 (2026-07-23 개정: 멀티 행 통합 시트 방식)

> 개정 배경: 동작별 개별 생성은 시트 간 일관성·위치 조정 문제가 커서, **레퍼런스 이미지 첨부 + 여러 동작을 행별로 담은 통합 시트 1장** 생성 방식으로 전환한다.

1. **`SpriteSheetPromptWizard : EditorWindow`** — 메뉴 `Tools/MCP/Sprite Sheet`
   - 기본 모드는 **레퍼런스 이미지 첨부 전제** 프롬프트: "Use the attached reference image as the exact character design reference" + 스타일/디자인 유지 지시. 캐릭터 설명(자유 텍스트)은 보존할 특징 서술용 선택 입력(레퍼런스 없이 생성할 때의 대체 수단 겸용).
   - **동작 행 목록 편집**: 행 추가/삭제, 행별 동작명(walk/run/attack/death 프리셋 + 직접 입력)과 프레임 수 지정. 기본값: walk 8, run 8, attack 8, death 10. 행별 연출 지시(예: attack의 anticipation~recovery, death의 시작·끝 포즈)는 프리셋에 내장.
   - 공통 옵션: 셀 크기(기본 256), 바라보는 방향(기본 오른쪽), 배경(흰색 단색 기본 — 임포트 시 제거 전제 / 투명 선택), 뷰(측면 고정 권장).
   - 프롬프트는 검증된 구조를 템플릿화: 카메라 고정, 일정 스케일, 지면 일정, 프레임 중앙 배치, 전신 노출, 모션블러/소품/추가 캐릭터/텍스트/장식 금지, 프레임 간 일관성 요구, 균등 그리드, 개별 프레임 명명(`walk_01`~) 조건부 요청 포함.
   - **게임 컨텍스트 입력** (2026-07-23 추가 개편): 게임 장르(자유 텍스트), 아트 스타일/분위기(자유 텍스트), 추가 참고 사항(선택). 레퍼런스 이미지 사용 토글과 캐릭터 설명(레퍼런스 미사용 시 필수)은 별도로 유지.
   - **로컬 AI CLI 기반 프롬프트 생성 (기본 경로)**: `AiCliRunner`로 감지한 AI CLI(claude/codex/gemini 등)를 드롭다운에서 선택하고, 검증된 템플릿 구조를 예시로 포함한 메타 프롬프트(`SpriteSheetPromptBuilder.BuildMetaPrompt`)를 async/await로 헤드리스 실행(취소 지원, 에디터 블로킹 없음)해 게임 컨텍스트가 반영된 프롬프트를 생성. AI 출력은 공백/코드펜스만 최소 정리. **폴백**: CLI 미설치/실행 실패/빈 응답 시 템플릿 방식(`BuildPrompt`)으로 생성하고 사유를 안내. "프롬프트 생성 (템플릿)" 버튼도 유지(빠른 생성). 템플릿도 게임 컨텍스트 반영("for a {genre} game", 스타일 유지 문장에 artStyle 삽입, notes는 Important requirements에 부가).
   - 미리보기 + 클립보드 복사, 답변/프롬프트(게임 컨텍스트, promptSource 포함)를 `Assets/Docs/SpriteSheetPrompt_{id}.json` 저장.
2. **`SpriteSheetImporter`** — 격자 기준 슬라이스 + 임포트 (같은 창 내 별도 섹션, 2026-07-23 격자 전용으로 확정)
   - 입력: 시트 이미지 파일(png) + 행 정의 목록(동작명 + 기대 프레임 수 — 이름·정보 표기용) + 배경 모드(흰색/투명)
   - **흰 배경 제거**: 이미지 네 외곽 전체 픽셀을 시드로 하는 큐 기반 BFS(4방향). 이웃 편입 조건: 채널별 최대 차 ≤ 16(그라데이션·격자선 추종) OR (min(R,G,B) ≥ 235 AND 3x3 윈도 전체가 근사 흰색/배경 — 흰 캐릭터 침식 방지). **채도(max-min) > 18인 유채색 픽셀은 어떤 경로로도 편입 금지** — 글로우/마법진 이펙트 보존. BFS 후 fringe 정리 1회 + **pocket restore**(제거 마스크 2px 침식 후 외곽 도달 불가 영역을 원본 알파로 복원 — 좁은 틈으로 샌 침식 복구).
   - **격자 슬라이스 (유일 경로)**: 전경 픽셀이 희소(교차 길이의 1% 미만)한 스캔라인 연속 구간(최소 두께 2px)의 중앙을 셀 경계로 검출 → 오검출 경계 정리(셀 크기가 중앙값의 40% 미만이면 이웃과 병합) → **누락 경계 복원**(셀 크기가 중앙값 피치의 1.6배 이상이면 round(크기/피치)개로 균등 분할 — 이펙트가 격자선을 덮은 경우 대응) → 셀 콘텐츠 판정(전경 ≥ 셀 면적 0.5%) → 출력 셀 = 최대 셀 크기(짝수 올림), 각 셀 콘텐츠는 **셀 내 상대 좌표 그대로 복사**(재정렬 없음 — AI가 그린 배치 신뢰). 완전 빈 그리드 행 제외, 행별 트레일링 빈 셀만 제거(중간 빈 셀은 위치 유지·슬라이스 미생성).
   - **격자가 곧 정답**: 행/프레임 수가 행 정의와 달라도 확인 없이 검출된 격자 그대로 임포트 (행 이름은 순서대로 행 정의의 동작명, 초과 행은 `rowN`; 차이는 결과 메시지에 정보로만 표기). 격자 검출 실패 시 원인·조치 안내 예외(격자선 있는 시트로 재생성 안내).
   - `TextureImporter`로 Sprite Mode=Multiple, 행별 동작명 기반 슬라이스 이름(`walk_01`~`death_10`), alphaIsTransparency, PPU=`MCPToolSettings.spritePixelsPerUnit` 적용
   - 프롬프트 템플릿은 격자선 그리기 + 셀 내부 순백(#FFFFFF)·무그라데이션·무그림자 + 바깥 여백 0(가장 바깥 격자선 = 이미지 가장자리) + 시트 전체 지면 기준선 통일을 지시
3. **MCP 도구 노출**
   - `mcptools_spritesheet_build_prompt` — 답변 파라미터(행 정의 목록 + 게임 컨텍스트 genre/artStyle/notes) → 프롬프트 문자열 + 저장 경로 반환. MCP 경로는 호출 주체가 이미 AI이므로 템플릿 방식 유지(CLI 재호출 없음)
   - `mcptools_spritesheet_import` — `imagePath`, 행 정의("walk:8,run:8,attack:8,death:10" 문자열), 배경 모드(white/transparent) → 슬라이스된 시트 경로 + 행/프레임 검출 결과(기대/검출 구성, usedDetectedLayout 포함) 반환. 격자 검출 결과가 항상 우선(불일치 확인 없음)

## 3. 규칙

- ComfyUI에 의존하지 않는다 (외부 AI 결과물 수동 투입 전제).
- 코드는 `MCPTools.Editor` 네임스페이스, `Editor/SpriteSheet/` 폴더에 배치.
- 픽셀 조작은 `Texture2D.GetPixels32` 기반, 에디터 블로킹 최소화(대형 이미지는 진행률 표시).
