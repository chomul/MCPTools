## 버전 3중 동기 (가장 중요)

릴리스마다 아래 **세 곳을 항상 같은 값으로** 올린다. 하나라도 어긋나면 Package Manager UI의 버전 표시와 실제 코드가 달라진다.

| # | 위치 | 형식 |
|---|------|------|
| 1 | `MCPToolTest/Assets/MCPTools/package.json`의 `version` | `0.1.0` |
| 2 | `MCPToolTest/Assets/MCPTools/Runtime/Data/MCPToolsInfo.cs`의 `Version` 상수 | `"0.1.0"` |
| 3 | git 태그 | `v0.1.0` (앞에 `v`) |

버전 규칙은 [semver](https://semver.org/lang/ko/) — 호환 깨지는 변경은 MAJOR, 기능 추가는 MINOR, 버그 수정은 PATCH.

## 릴리스 순서

1. **CHANGELOG 갱신** — `MCPToolTest/Assets/MCPTools/CHANGELOG.md`의 `[미배포]` 섹션을 `[X.Y.Z] - YYYY-MM-DD`로 확정하고 Added/Changed/Fixed를 정리한다.
2. **버전 3중 동기** — 위 표의 세 곳을 모두 갱신한다 (태그는 4번에서).
3. **커밋 전 점검** (아래 §점검 목록)
4. **커밋 → 태그 → 푸시**
   ```bash
   git add -A
   git commit -m "release: v0.1.0"
   git tag v0.1.0
   git push origin main --tags
   ```
5. **설치 검증** — 빈 Unity 6 프로젝트에서 위 설치 URL(`#v0.1.0`)로 설치해 [Task7 체크리스트 §5.5](checklist/Task7_체크리스트.md)를 수행한다. 최소한 ① 컴파일 오류 0, ② 설정 에셋이 `Assets/MCPTools.User/`에 생성, ③ [서버 시작]으로 브리지가 PackageCache에서 기동되는지는 매 릴리스 확인한다.

## 커밋 전 점검 목록

> **⚠️ 새 파일을 추가한 뒤에는 반드시 Unity 에디터를 한 번 열어 `.meta`를 생성시킨 다음 커밋한다.**
> `.meta`는 Unity가 만들도록 두는 것이 원칙이라(직접 만들지 않는다) 에디터를 열기 전에는 새 파일에 `.meta`가 없다.
> 그 상태로 커밋하면 사용자 프로젝트에서 GUID가 새로 생성되어 asmdef 참조·에셋 참조가 깨진다.

- [ ] **`.meta` 누락 없음** — 패키지 에셋은 GUID로 참조되므로 `.meta`가 빠지면 사용자 프로젝트에서 참조가 깨진다. `.gitignore`에 `*.meta`를 넣지 않았는지 확인하고, 아래로 짝이 맞는지 본다.
  ```bash
  # .meta 없는 파일 찾기 (결과가 비어야 정상)
  git ls-files 'MCPToolTest/Assets/MCPTools/*' | grep -v '\.meta$' | grep -v 'Server~' \
    | while read f; do [ -f "$f.meta" ] || echo "META 누락: $f"; done
  ```
- [ ] **개인 값 미포함** — `MCPToolSettings.asset`은 `.gitignore` 대상이다. 실수로 추가되지 않았는지 확인한다.
  ```bash
  git ls-files | grep -i 'MCPToolSettings.asset'   # 결과가 비어야 정상
  ```
- [ ] **`Server~/` 포함** — 브리지 서버는 Unity가 임포트하지 않지만 **git에는 반드시 커밋되어야** 한다. 빠지면 3단계가 전혀 동작하지 않는다.
  ```bash
  git ls-files | grep 'Server~'   # bridge_server.py, variables.json, workflows/*.json 5종이 보여야 정상
  ```
- [ ] **LFS 미사용** — UPM git 설치는 LFS를 지원하지 않는다. 패키지 폴더 안의 파일이 LFS로 추적되면 사용자에게 포인터 텍스트가 내려간다.
  ```bash
  git lfs ls-files 2>/dev/null | grep 'Assets/MCPTools/'   # 결과가 비어야 정상
  ```
- [ ] **저장소 크기** — `MCPToolTest/Library/`(2GB+)가 무시되고 있는지. `git count-objects -vH`로 확인.
- [ ] **`package.json` 유효성** — `python -c "import json;json.load(open('MCPToolTest/Assets/MCPTools/package.json',encoding='utf-8'))"`

## 사용자 쪽 업데이트 방법 (README에도 기재)

- `Packages/manifest.json`의 URL에서 `#vX.Y.Z` 태그를 새 버전으로 바꾼다.
- 또는 Package Manager에서 패키지를 **Remove 후 새 URL로 재추가**한다.
- 태그를 생략하면 기본 브랜치 HEAD를 받으므로 재현성이 없다. **배포용 URL에는 항상 태그를 붙인다.**

> 사용자가 `Assets/MCPTools.User/`에 만든 설정·템플릿·워크플로 사본은 패키지 업데이트의 영향을 받지 않는다. 반대로 **패키지 폴더 안을 직접 고친 내용은 업데이트 시 소실된다.**
